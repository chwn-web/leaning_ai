# 会话同步与备份（两台电脑 + 防重置）

> 目标：①公司机器 ↔ 家里机器接着聊；②这台机器可能重置，记录不能丢；③（远期）自己做一个插件上架。
> 本机实测：DSH `0.2.2-rc.1`、Node `v24.21.0`、git `2.46.0`、`~/.dsh/sessions` 19 文件 / 18.9 MB、`~/.dsh/attachments` 39 文件 / 3.6 MB。

## 一、先分清三件事

| 你要的 | 技术含义 | 谁负责 |
|---|---|---|
| 两台电脑接着聊 | 会话事件流跨机同步 + 冲突不丢 | 插件 |
| 重置后能恢复 | 会话 + 附件的**异机备份**（不是同步） | 插件远端 / 手动导出 |
| 学习资料可追 | 计划文档与代码在 git 仓库 | 已有（本仓库） |

**重要事实**：`~/.dsh/sessions/<编码后的工作区路径>/<会话id>/session.v4.jsonl.zstd`
——工作区路径被编码进目录名（本机是 `--D-TCL-leaning_AI_agent--`）。两台机器路径不一致时，"同步过来的会话"会挂到一个本机不存在的路径上。

## 三、我的推荐（按你的两个诉求）

**推荐 A：`dsh-session-sync`（PerryLink）+ 私有仓库 + 两台机器统一工作区路径**

- 一条链路同时满足"同步"和"备份"：会话字节镜像进你自己的 git 仓库，重置后 `git clone` + `/sync pull` 即可拉回。
- 必须做两件事：①仓库**私有**（会话里有 TCL 业务内容），或开 `backend: encrypted`；②家里那台也把工作区建成 `D:\TCL\leaning_AI_agent`，路径一致就不会出现"会话挂空"。
- 代价：整仓镜像包含全部会话（含别的项目），每次改动都是新 blob，仓库会慢慢变大（插件无分页清理）。

**备选 B：`@linbin-mk/dsh-session-sync`**

- 适合"只想同步这一个学习项目、且两台机器路径不一样"：按工作区名匹配、逐会话勾选、有 UI。
- 代价：要手动勾选；不加密；只在有同名工作区时自动落位。

**兜底 C：不装插件（今天就能做，10 分钟）**

1. 会话：DSH 自带 `/export`（或 Session Header 的 "Session log"）→ 下载 ZIP 存网盘；
2. 附件：拷 `C:\Users\issuser\.dsh\attachments`；
3. 结论与代码：本仓库（已推 GitHub，`git clone` 即续接）。

## 四、安全红线

- GitHub 仓库**目前是公开的**，里面有公司名、审核平台业务、面试素材 → 会话同步仓库**必须新建为私有**，不要复用 `leaning_ai`。
- 插件拥有 `filesystem:read/write`、`subprocess:git` 权限，装之前看一眼它的 README"安全边界"章节（两个候选都写了，PerryLink 那份尤其细）。
- 别把整个 `.dsh` 放进 OneDrive/坚果云实时同步：`storages/`、`session.lock` 会争用，损坏风险高。

## 五、如果要自己做一个上架（差距分析）

现成插件的共同缺口，也就是可上架的点：

1. **只同步会话，不同步附件**：`~/.dsh/attachments`（3.6 MB）不在同步范围，会话里贴过的图到另一台就裂了。
2. **没有"换机迁移向导"**：装插件 → clone → 重建工作区 → 导入 → 校验，现在要人肉五步；做成一个按钮就是刚需。
3. **路径强耦合**：按路径编码的目录名 / 按名称匹配，改个目录名就掉链子；可以做成"路径无关 + 自动修复映射"。
4. **加密不默认**：默认明文，靠用户自觉；可以默认加密 + 密钥本地保管。
5. **没有"快照/时光机"**：只有最新态 + fork 文件，没有"回到上周三的会话状态"。

平台允许的落点：`ctx.sessionPersistence`（可自实现持久化后端）、`webServer` 路由（注册同源 HTTP API）、`settings.section` / `sidebar.*` / `shell.overlay` 插槽（自带 UI）、`dsh.bundle.patch`（一行安装）。评审最看重的通常是：**默认安全**、**失败时不丢数据**、**装完 30 秒内能验证成功**。
