## 关键设计决定（以及为什么）

1. **按字节搬运，不解析会话内容** —— 会话语义是私有约定，解析等于把上游格式写死进插件。代价：不知道附件、无法判断 turn 是否闭合（只能靠"文件 30 秒没变化"近似）。
2. **git 只当传输层** —— 远端可以是任意私有 git 仓库，零服务端、零运维、天然有时间旅行。
3. **默认「仅本机」的开关默认是 cloud？** 不。**未记录的会话按 cloud 走**（保证"重置也不丢"），用户可逐条切成 local；`push` 会跳过 local（`--include-local` 可强制），且**不回写** mode。
4. **装到 tauri profile**，不是 web profile —— 桌面版读 `~/.dsh/profiles/tauri`（junction → `D:\DSH\plugin`）。
5. **客户端 chip 用 `position: absolute`** —— 宿主正文祖先带 `transform`，`fixed` 会被解析成相对祖先（曾经的"菜单跑到右下角"）。
6. **不用 `window.confirm`** —— Tauri WebView 里不可靠，改成菜单内确认面板。

## 已验证的证据（别重复验证）

- 打包→push→pull 往返：sha256 完全一致（会话 `4ae16c7d` 288,718 B / `session-f2cbe70e` 3843.5 KB 都试过）
- 拉到全新空目录后 zstd 首行 header 可解析：`id` / `cwd=D:\TCL\leaning_AI_agent` / `version=4`
- 换机演练：把本地会话目录整体移走 → `pull` 回来 → 文件重现且 sha 一致（`DESIGN.md` §13.1）
- `python selftest.py`：21/21 全绿（含 5MB 会话、中文/空格路径、跨工作区同名、state 损坏降级、远端不可达、pull 幂等）
- 宿主接口：`GET /session-cloud/health` → 200，`pkgDir` 指向 `D:\DSH\plugin\node_modules\dsh-session-anywhere`
- 「仅本机」真的不上传：云端 index 的 sha 停在上次同步值，本机文件已变 → 内容没传
- 市场收录规则已核对（`awesome-dsh-plugin/contributing.md`）：需 `dsh.bundle` manifest、仓库满 1 天、topic `dsh-plugin`、真实代码

## 风险（照抄，别忘）

- 会话不加密进私有仓库 → 泄露面在"仓库设错公开 / 账号被盗"
- 依赖本机 Python 3.11+ 和 git → 大部分 issue 会来自这里
- 私有格式 `session.v4.jsonl.zstd` 一升级就可能全废（不解析已把影响降到最小）
- 跨机工作区路径不同 → 落到不同目录（`wsKey` 由绝对路径编码）
- 发布不可逆：包名/版本号永久占用

## 常用命令

```powershell
# 引擎
python plugins/session-cloud/sync.py status
python plugins/session-cloud/sync.py mode --session <id> --to cloud|local
python plugins/session-cloud/sync.py push --all --force
python plugins/session-cloud/sync.py pull --all
python plugins/session-cloud/selftest.py

# 宿主自检
Invoke-RestMethod http://127.0.0.1:3080/session-cloud/health

# 手动触发备份
schtasks /Run /TN "DSH-Session-Backup"

# 回滚插件（起不来时）
Copy-Item "$env:USERPROFILE\.dsh\profiles\tauri\package.json.bak-session-cloud" "$env:USERPROFILE\.dsh\profiles\tauri\package.json" -Force
```
