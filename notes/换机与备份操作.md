# 换机与备份操作（DSH 会话）

> 目标：这台电脑可能重置，家里的电脑要能接着聊。
> 原理：会话就是磁盘上的一个文件，原样搬到私有 git 仓库，再原样搬回来即可（不解析、不改写）。
> 设计依据见 [DESIGN.md](../plugins/session-cloud/DESIGN.md)，引擎用法见 [README.md](../plugins/session-cloud/README.md)。

## 现状（2026-11-10 已开通并验证）

- 私有仓库：`https://github.com/chwn-web/dsh-sessions-private.git`（**已用无痕窗口确认：未登录访问返回 404 = 私有**）
- 已推送：11 条会话 + 11 条索引（最新提交见仓库）
- **自动备份**：计划任务 `DSH-Session-Backup`，每 2 小时一次，日志 `.tmp-backup.log`
- 演练：真实删掉本地会话目录再从仓库拉回，sha256 逐字节一致、header 可解析（详见 DESIGN.md §13.1）

## 1. 平时：已经自动了（不用手动操作）

已建好 Windows 计划任务 **`DSH-Session-Backup`**：**每 2 小时**自动把全部会话推到私有仓库（登录状态下生效）。

查看它跑得怎么样：

```powershell
schtasks /Query /TN "DSH-Session-Backup" /FO LIST /V | Select-String "Last Result|Next Run"
Get-Content D:\TCL\leaning_AI_agent\.tmp-backup.log -Tail 20
```

- `Last Result: 0` = 成功；非 0 = 看日志最后一行的 `❌ 备份失败`
- 想手动立刻备份一次：`schtasks /Run /TN "DSH-Session-Backup"`
- 想关掉：`schtasks /Change /TN "DSH-Session-Backup" /DISABLE`（重新开用 `/ENABLE`）
- 想改成别的时间间隔：删了重建，例如每 30 分钟
  `schtasks /Delete /TN "DSH-Session-Backup" /F` 然后 `/Create ... /SC MINUTE /MO 30`

也可以在普通 PowerShell 里手动跑（同样有效，输出直接看屏幕）：

```powershell
cd D:\TCL\leaning_AI_agent
powershell -File scripts\session-backup.ps1
```

> 正在进行的这条会话文件还在写，`--force` 会把它当前的样子一起推上去（可能尾部不完整）。
> 不用管：DSH 加载时会自动修复未闭合的 turn，下次备份又会覆盖成更新的版本。

## 2. 换电脑前（重置前）：确认最后一次备份

```powershell
cd D:\TCL\leaning_AI_agent\plugins\session-cloud
python sync.py status          # 每行最后一列应显示 ☁ 云同步
powershell -File ..\..\scripts\session-backup.ps1
```

然后去 GitHub 上看一眼 `dsh-sessions-private` 的最新提交时间是不是刚才。

## 3. 新电脑：装好 DSH 之后拉回

前提：新机器的工作区路径与旧机器一致（`D:\TCL\leaning_AI_agent`），否则会话会落到另一个项目目录下（能用，但侧栏分组不同）。

```powershell
# ① 拿到引擎（clone 学习仓库即可，里面有 sync.py）
git clone https://github.com/chwn-web/leaning_ai.git D:\TCL\leaning_AI_agent

# ② 配远端
cd D:\TCL\leaning_AI_agent\plugins\session-cloud
python sync.py config --remote https://github.com/chwn-web/dsh-sessions-private.git

# ③ 拉回本机 sessions 根目录
python sync.py pull --all

# ④ 验证
python sync.py status
```

**然后重启 DSH**（或刷新页面），侧栏里会话就回来了。

## 4. 三条硬规矩（踩过坑才写下来的）

1. **不要在 `~/.dsh/sessions/` 里留备份副本**——哪怕改名成 `.bak`。扫描器发现同一 id 两份会抛 `duplicate JSONL session id`，整个列表报废。备份只在 git 仓库里。
2. **不要用 OneDrive/坚果云同步整个 `~/.dsh`**——`storages/`、`session.lock` 会被两个进程同时写，容易坏。
3. **仓库必须私有**。想确认是不是私有：开无痕窗口访问 `https://github.com/chwn-web/dsh-sessions-private`，应显示 404。

## 5. 出问题怎么退

- 拉回来列表里没有 → 看 `python sync.py status` 有没有 ☁ 标记；再确认文件确实落在 `C:\Users\<你>\.dsh\sessions\--D-TCL-leaning_AI_agent--\<会话id>\session.v4.jsonl.zstd`
- 列表报 `duplicate JSONL session id` → 去 sessions 根目录找出重复的会话 id（通常是手贱复制的备份目录），删掉多余那份
- 推送报 `couldn't create signal pipe` → 你在 DSH 沙箱里跑了，换到普通 PowerShell 窗口
