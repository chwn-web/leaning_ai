# 排障四轴：先定轴，再动手

> 线上问题永远落在这四轴之一：**质量 / 延迟 / 成本 / 稳定**。
> 不定轴就开始改 prompt，是新手最典型的浪费——改完你连"有没有修好"都说不清。

## 一、定轴（30 秒判断）

| 用户/业务怎么说 | 轴 | 第一反应 |
|---|---|---|
| "答得不对/答非所问/胡说" | 质量 | 跑 golden 看是否复现 |
| "太慢了/转圈半天" | 延迟 | 看 TTFT 还是总时长 |
| "账单怎么涨了" | 成本 | 拆输入/输出/调用数 |
| "报错/卡住/重复执行" | 稳定 | 看 trace 停在哪一步 |

一个现象可能同时属于两轴（"又慢又贵"通常是上下文太长），**先修影响业务的那一轴**。

## 二、通用五步（顺序不要跳）

```
① 复现：同一输入能否稳定复现？能→看代码/模型版本；不能→看数据分布/并发/时间
② 定位层：用 trace 判断停在哪一层（L6 体验 / L5 编排 / L4 上下文 / L3 模型 / L2 工具 / L1 数据）
③ 二分：把链路切成两半，分别测（检索 vs 生成、单步 vs 多步、模型 vs 工具）
④ 归因：找出"唯一变量"——版本？数据？流量？配置？
⑤ 修复 + 回归：改完必须跑同一份 golden，并补一条用例防止复发
```

**第 ⑤ 步的"补一条用例"是分水岭**：只修不补，同类问题一定复发。

## 三、四轴各自的检查清单

### 质量（答得不对）

| 顺序 | 查什么 | 怎么查 |
|---|---|---|
| 1 | 答案在不在检索结果里 | 看 trace 里的召回片段；不在 → 检索责任 |
| 2 | 检索到了但没进上下文 | 看拼装后的 token 与截断位置 |
| 3 | 进了上下文但答错 | 看 prompt 里指令与证据的位置（中间位置最弱） |
| 4 | 模型/参数变了 | 对比模型版本、温度、max_tokens |
| 5 | 数据变了 | 新增/删除的文档、解析失败率、embedding 版本 |
| 6 | 评测本身坏了 | judge 版本、样本被改动、数据集污染 |

### 延迟（太慢）

| 顺序 | 查什么 | 典型值 |
|---|---|---|
| 1 | TTFT vs 总时长 | TTFT 大 → 输入太长/缓存未命中；总时长长 → 输出太长或多步 |
| 2 | 步数是否变多 | 平均步数上移说明工具或提示变差 |
| 3 | 并行是否退化为串行 | 同一步的多个工具是否被串行执行 |
| 4 | 单步慢在哪 | 检索/rerank/工具超时/模型排队 |
| 5 | 是否被限流 | 429/排队 → 需要队列与背压 |

### 成本（太贵）

| 顺序 | 查什么 | 手段 |
|---|---|---|
| 1 | 拆三本账 | 输入 token / 输出 token / 缓存命中 |
| 2 | 调用数 | 步数 × 每步调用数；是否有重试风暴 |
| 3 | 上下文膨胀 | 检索条数、历史长度、工具返回长度 |
| 4 | 模型档位 | 是否所有请求都用了最贵的模型 |
| 5 | 异常流量 | 某租户/某用户刷量（要有每租户配额） |

### 稳定（报错/卡住/重复）

| 顺序 | 查什么 | 典型坑 |
|---|---|---|
| 1 | 超时被当"没发生" | 重试导致重复写入（P15） |
| 2 | 重试风暴 | 无上限重试 + 无退避（P4） |
| 3 | 并发打崩 | 连接池/限流/内存（P13） |
| 4 | 死循环 | 动作签名重复、无进展检测 |
| 5 | 状态不一致 | 并行 agent 覆盖、事务边界 |

## 四、经典场景 → 直接跳到答案

| 场景 | 根因大概率是 | 详见 |
|---|---|---|
| 上线一周质量掉 12 个点，没人改代码 | 数据/索引变化（新文档、删除未传播、embedding 版本） | [08-rag](../02-概念/08-rag.md) |
| 10 路并发正常，50 路全 429 | 没有队列与背压、没做租户限额 | 题库 P13 |
| 一夜烧掉 $1800 | 重试风暴 + 无预算守卫 | 题库 P4 |
| 第 12 轮开始"忘记"前面的要求 | 上下文压缩腐化 | [02-上下文工程](../02-概念/02-上下文工程.md) |
| 有权限的文档查不出来 | 先取 top-k 再过滤（后过滤） | 题库 P7 |
| 今天 82 分明天 76 分 | 评测不可复现（温度/版本/judge） | [10-评测](../02-概念/10-评测.md) |

## 五、不要做的事

- ❌ 一上来就改 prompt（它可能是唯一没问题的部分）。
- ❌ 用"我觉得"代替基线数据。
- ❌ 只修不补用例。
- ❌ 在没复现的情况下上线修复（等于赌博）。
- ❌ 同时改两个变量（改完不知道是谁起的作用）。
