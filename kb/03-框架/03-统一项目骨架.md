# 统一项目骨架：5 个项目共用一套分层，面试时才能讲"我的标准做法"

> 代码在 `projects/_template/`。**它不是为了跑起来好看，是为了让你每个项目都能回答"这一块属于哪一层"。**
> 一个能复用 5 次的骨架，比 5 个各写各的 demo 值钱——因为面试官问的是"你怎么组织一个 Agent 项目"。

## 1. 目录 → 七层映射（背这张表）

| 目录/文件 | 层 | 一句话职责 | 面试怎么说 |
|---|---|---|---|
| `src/main.ts` | L6→L5 入口 | 组装依赖、跑一次任务、打印结果 | "入口只做装配，不含业务逻辑" |
| `src/core/types.ts` | 全局 | 跨层契约（Message/ToolSpec/ToolResult/Span） | "先定契约再写实现" |
| `src/core/errors.ts` | L0 | 错误分类（transient/permanent/policy/permission/validation/budget） | "不同错误不同处置，只有 transient 才重试" |
| `src/core/budget.ts` | L5 | 步数/花费/墙钟三重预算 | "系统必须自己决定什么时候停" |
| `src/core/validate.ts` | L2 | 手写 schema 校验 | "模型参数一律当不可信输入" |
| `src/llm/provider.ts` | L3 | Provider 接口 + Mock + OpenAI 兼容 + 重试 | "换模型只改这里，上层不动" |
| `src/tools/registry.ts` | L2 | 注册/校验/执行/超时/幂等/错误回填 | "工具层是安全边界" |
| `src/tools/builtin.ts` | L2 | 三个示范工具（算/读/写） | "读带 ACL，写要确认" |
| `src/agent/loop.ts` | L5 | 有界循环 + 动作签名去重 + 并行工具 | "循环必须有四个停止条件" |
| `src/obs/tracer.ts` | L0 | span、JSONL trace、summary | "没有 trace 就不可能排障" |
| `src/eval/dataset.ts` | L0 | golden set 加载 | "评测集和数据同仓版本化" |
| `src/eval/runner.ts` | L0 | pass@k / pass^k / CI / 失败分布 | "报数要带样本量和置信区间" |
| `src/eval/run.ts` | L0 | CLI 出报告 | "跑一条命令就能回归" |
| `data/golden.jsonl` | L0 | 10 条分层样本 | "评测样本覆盖边界与对抗" |
| `docs/adr/` | — | 架构决策记录 | "每个反直觉的决定都留了原因" |

**自检**：随便指一个文件，你能说出它属于哪一层、它挂了会怎样吗？

## 2. 怎么复制它开新项目

```powershell
cd D:\TCL\leaning_AI_agent\projects
Copy-Item -Recurse _template p0-llm-gateway
cd p0-llm-gateway
# 改 package.json 的 name
node src/main.ts        # 先确认骨架还能跑
```

原则：**先复制再改造，永远不要从空白目录开始**——空白目录会让你重新发明分层，第 3 个项目就乱了。

## 3. 改 3 个文件，它就变成你的项目

| 改哪个 | P0 网关 | P1 工具 Agent | P2 知识库 | P3 平台 | P4 垂直产品 |
|---|---|---|---|---|---|
| `src/llm/provider.ts` | 多家 provider + 路由 + 缓存 | 保持 | 保持 | 保持 + 租户配额 | 保持 |
| `src/tools/builtin.ts` | 加"成本预估"工具 | 换成你的 3 个业务工具 | 换成 `search_docs` 真实版 | 工具网关 + 权限 | 业务工具集 |
| `src/eval/run.ts` | 模型对比评测 | 工具调用评测 | recall@k + faithfulness | 多租户隔离评测 | 端到端任务评测 |
| 额外新增 | `src/router/` | `src/agent/planner.ts` | `src/retrieval/` | `src/tenant/`、`mcp/` | `web/` 前端 + HITL |

## 4. 五个项目的差异化（都在同一骨架上长）

| 项目 | 骨架之上加什么 | 验收（写进 README） |
|---|---|---|
| **P0 多模型网关** | 路由（按难度/成本）、重试与熔断、成本看板、prompt cache | 同一任务在 2 个模型上跑同一份 golden，出对比表（成功率/成本/p95） |
| **P1 工具 Agent** | 3–5 个业务工具、写操作幂等、人工确认、循环检测 | golden ≥ 30 条，报 pass^k 与失败分布；演示一次参数校验失败被自愈 |
| **P2 知识库 Agent** | 解析/切分/混合检索/rerank/ACL/引用 | recall@k 与端到端成功率都报；权限用例 100% 不越权；无答案正确 abstain |
| **P3 平台** | 租户隔离、MCP server、可视化编排、trace 链路、配额计费 | 10 并发压测 p95；跨租户红队用例全拦；开源 README + 架构图 |
| **P4 垂直产品** | 前端流式 UI + HITL + 真实用户 | ≥10 个真实用户跑通端到端；有一个真实客户/同事在用 |

## 5. "故意没做"的清单（面试被问到时如实说，这是加分项）

模板里**刻意没有**：真实模型调用（只留实现）、数据库、向量库、UI、部署、鉴权服务、多租户。

原因：这些是**每个项目都不同**的部分，骨架只固化"每层都必须存在"这件事。被问"你怎么不做全"时，正确回答是：
> "骨架只固化分层与契约，具体依赖按项目换。这样 5 个项目共享同一套心智模型，我换项目时只需要换实现，不用重新设计结构。"

## 6. 演进顺序（别一上来就抽象）

```
第 1 周：main.ts 里跑通一次调用（不分层，别管架构）
第 2 周：抽出 provider（换模型不痛了）
第 3 周：抽出 tools（工具超过 2 个就会有重复代码）
第 4 周：抽出 loop（出现"要跑多步"的需求）
第 5 周：加 budget + tracer（第一次跑飞/第一次看不懂日志）
第 6 周：加 eval（第一次被问"你怎么知道变好了"）
```
**每一层都是被痛点逼出来的，不是提前设计的。**这条演进史本身就是面试素材。
