# 术语表：中英对照 + 一句话 + 最容易搞混的地方

> 用法：看不懂英文文档、面试听不懂名词、写简历想用对词——查这里。
> **"易混"列是重点**：大部分面试翻车不是不知道这个词，而是把两个词当成了一个。

## A. 模型与推理

| 中文 | 英文/缩写 | 一句话 | 易混点 |
|---|---|---|---|
| 上下文窗口 | context window | 一次请求能吃进去的 token 上限 | ≠ 有效窗口（中间会失效） |
| 键值缓存 | KV cache | 缓存已算过的注意力，省重复计算 | 是显存开销，不是磁盘缓存 |
| 分组查询注意力 | GQA | 多个 query 头共享一组 KV 头，省显存 | 与 MQA（全部共享）不同 |
| 首 token 延迟 | TTFT | 第一个 token 出来的时间 | ≠ 总延迟；流式体验看它 |
| 采样温度 | temperature | 控制随机性 | =0 也不可复现 |
| 核采样 | top-p / nucleus | 从累计概率 p 的候选里采 | 与 top-k 是两种截断方式 |
| 投机解码 | speculative decoding | 小模型起草、大模型校验，提速 | 不改变输出分布（理论上） |
| 混合专家 | MoE | 每 token 只激活部分参数 | 会导致同输入不同输出 |
| 量化 | quantization | 用低精度表示权重，省显存 | 有精度损失，评测要重跑 |

## B. 上下文与提示

| 中文 | 英文/缩写 | 一句话 | 易混点 |
|---|---|---|---|
| 提示工程 | prompt engineering | 优化指令与示例 | 已被"上下文工程"包含 |
| 上下文工程 | context engineering | 决定放什么信息、放哪、何时丢 | 不只是改措辞 |
| 系统提示 | system prompt | 全局规则与角色 | 不是安全边界 |
| 少样本 | few-shot | 给几个示例 | 示例太多反而降效 |
| 思维链 | CoT | 让模型先推理再回答 | 推理链可能"编"得很像 |
| 结构化输出 | structured output | 按 schema 输出 | 合法 ≠ 正确 |
| 约束解码 | constrained decoding | 解码时屏蔽非法 token | 会增加延迟 |
| 提示缓存 | prompt/prefix cache | 复用相同前缀的计算 | 前缀一变就失效 |
| 中间迷失 | lost in the middle | 长上下文中间信息召回弱 | 与 context rot 相关但不同 |
| 上下文腐化 | context rot | 输入变长后性能非均匀下降 | 不是"忘"，是"分不清主次" |

## C. 检索与知识

| 中文 | 英文/缩写 | 一句话 | 易混点 |
|---|---|---|---|
| 检索增强生成 | RAG | 先检索再生成 | ≠ 微调 |
| 向量化/嵌入 | embedding | 把文本映射成向量 | 换模型必须重灌 |
| 分块 | chunking | 把文档切成检索单元 | 小块搜、大块喂（父子块） |
| 混合检索 | hybrid retrieval | 关键词 + 向量并用 | 谁主导要看查询类型 |
| 倒数排名融合 | RRF | 按名次融合多路结果 | 不需要分数可比 |
| 重排 | rerank | 用 cross-encoder 对少量候选精排 | 救不了没召回的 |
| 召回率@k | recall@k | 前 k 条里含相关结果的比例 | 与精确率成对看 |
| 平均倒数排名 | MRR | 第一个相关结果名次的倒数均值 | 只看第一个 |
| 归一化折损累计增益 | nDCG | 考虑位置的排序质量 | 多级相关性用 |
| 权限预过滤 | ACL pre-filter | 检索时带上权限条件 | 后过滤会把结果滤空 |
| 无答案 | abstain | 没有依据时说"不知道" | 是能力，不是缺陷 |

## D. Agent 与工具

| 中文 | 英文/缩写 | 一句话 | 易混点 |
|---|---|---|---|
| 智能体 | agent | 模型 + 工具 + 循环 + 状态 | ≠ 工作流 |
| 工作流 | workflow | 代码写死的执行路径 | 可控可测，长尾差 |
| 推理-行动循环 | ReAct | 思考与行动交替 | 与 Plan-Execute 不同 |
| 先规划再执行 | plan-and-execute | 先分解再逐步做 | 必须支持 replan |
| 函数调用 | function calling | 模型输出要调用哪个函数+参数 | 模型不执行 |
| 工具 | tool/function | 可被调用的能力 | 数量 >10 会变差 |
| 模型上下文协议 | MCP | 标准化的工具接入协议 | ≠ function calling 的替代品 |
| 交接 | handoff | agent 之间传任务 | 必须结构化，否则丢引用 |
| 人在环 | HITL | 关键步骤人工确认 | 不是"全人工审核" |
| 幂等 | idempotency | 同一操作重复执行结果一致 | 写操作用它防重复 |
| 检查点 | checkpoint | 长任务的状态快照 | 用于恢复，不是备份 |

## E. 评测与运维

| 中文 | 英文/缩写 | 一句话 | 易混点 |
|---|---|---|---|
| 评测 | evals | 用固定样本度量质量 | 不是"测试几十次看看" |
| 金标准集 | golden set | 人工标注的评测样本集 | 要版本化、要防污染 |
| 至少一次成功 | pass@k | k 次里有 1 次成功 | ≠ 生产可用性 |
| k 次全成功 | pass^k | k 次全成功 | **生产看这个** |
| 模型当裁判 | LLM-as-judge | 用模型给模型打分 | 有位置/冗长/自我偏好偏差 |
| 置信区间 | confidence interval | 指标的不确定范围 | 100 条约 ±8 分 |
| 可观测性 | observability | 能从外部推断内部状态 | 落地形态是 trace + 指标 |
| 跨度/链路 | span / trace | 一次操作 / 一串操作 | 多 agent 必须串 trace |
| 灰度 | canary | 小流量先上 | 要有回滚判据 |
| 死信 | dead letter | 反复失败进队列待处理 | 不是"丢掉" |

## F. 安全

| 中文 | 英文/缩写 | 一句话 | 易混点 |
|---|---|---|---|
| 提示注入 | prompt injection | 用文本操纵模型行为 | 分直接/间接 |
| 致命三要素 | lethal trifecta | 私有数据+不可信内容+外发通道 | 砍掉一个即可大幅降险 |
| 工具投毒 | tool poisoning | 恶意工具描述藏指令 | 来自供应链 |
| 越权 | privilege escalation | 用不该有的权限做事 | RAG 里最常见是后过滤 |
| 出站控制 | egress control | 限制能连哪些外部地址 | 最有效也最影响功能 |
| 沙箱 | sandbox | 隔离执行不可信代码 | 不是绝对安全 |

## 怎么用这张表（每周 5 分钟）

1. 遮住"一句话"列，看中文说解释；说不出来的做记号。
2. 遮住"易混点"，问自己"这两个词差在哪"。
3. 一周内遇到的新词，**追加到对应小节**（不要新建文件）。
