# 评测：没有置信区间的准确率，等于没有

**① 一句话定义**
用**固定样本 + 固定流程**度量系统质量，并能回答三个问题：改完是变好还是变坏、好多少、这个结论有多可信。

**② 它解决什么问题**
没有评测，"感觉这个 prompt 更好"就是唯一决策依据；换个模型、加个工具、改个切分，谁也不知道是回归还是提升。**面试里这道题几乎是必问**——因为它区分"做过 demo"和"上过线"。

**③ 关键机制**

| 机制 | 要点 |
|---|---|
| 样本分层 | happy path ／ 边界与歧义 ／ **无答案（该说不知道）** ／ 对抗（注入/越权）／ 工具失败（超时/非法参数） |
| 样本量 | 100 条时 95% 置信区间约 ±8 个百分点；400 条约 ±4。**20 条测出 95% 毫无意义（区间可能 76%–99%）** |
| 两个成功率 | **pass@k**＝k 次里至少成功一次（能力上限）；**pass^k**＝k 次全成功（生产看这个） |
| judge 偏差 | 位置偏差（换位）、冗长偏差（长度校正）、自我偏好（多模型陪审）、温度不一致（多票）、格式偏差（贴合训练格式）；细粒度事实判定不要全交给 judge |
| 可复现 | 锁模型版本/温度/seed、mock 工具、缓存输出、数据集版本化、judge 版本固定 |
| 落地方式 | 进 CI（回归门禁）+ 灰度（线上小流量）+ bad case 回流（真实失败进数据集） |
| 指标分层 | 检索（recall@k）→ 生成（faithfulness/citation）→ 任务（成功率）→ 体验（中断率/接管率） |

**④ 边界与代价**
- **数据污染**：样本进了训练集或你反复对着它调参 → 指标虚高（要留"从不给模型看"的 holdout）。
- 过拟合评测：为了分数调 prompt，线上分布一变全崩。
- judge 不可靠：它擅长"整体好不好"，不擅长"这个数字对不对"。
- 评测成本：跑一遍要钱要时间 → 分层跑（每次改动跑小集，发版跑全集）。

**⑤ 工程落点**
- `projects/_template/src/eval/dataset.ts` —— golden.jsonl 加载（坏行报行号并跳过）
- `projects/_template/src/eval/runner.ts` —— pass@k / pass^k / 失败按 tag 分布 / **正态近似 95% CI** / n<30 警告
- `projects/_template/src/eval/run.ts` —— `node src/eval/run.ts --k 3` 出报告
- 观察点：`data/golden.jsonl` 里故意设计的失败 case，看报告怎么把它分类出来

**⑥ 面试追问（三层）**
1. **怎么衡量**：报"样本量 + 成功率 + 置信区间 + 失败分布"，而不是一个孤零零的百分比。
2. **为什么不用另一方案**：为什么不用 LLM 当唯一裁判？→ 有系统性偏差、不可复现。为什么不只看用户满意度？→ 滞后、样本偏差、无法定位。
3. **线上坏了怎么定位**：先跑同一份 golden 看是否复现（复现=代码/模型变了，不复现=数据分布变了）→ 再分层看哪一类掉得最多 → 再回放 trace。
