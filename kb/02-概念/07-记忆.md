# 记忆：写入策略比检索策略更重要

**① 一句话定义**
让系统跨会话、跨任务保留并使用信息的能力。分三类：**working**（当前上下文里的临时状态）、**episodic**（历史事件/对话轨迹）、**semantic**（提炼出的稳定事实与偏好）。

**② 它解决什么问题**
窗口有限、会话结束即失忆，用户不想每次重复自己；长期任务需要知道"上次做到哪"。但"把所有历史塞回去"既贵又会让模型抓不住重点。

**③ 关键机制**

| 机制 | 要点 |
|---|---|
| 分离三类记忆 | working 用工作笔记；episodic 用事件表/向量；semantic 用结构化事实表（用户偏好、实体属性） |
| **写入策略**（最关键） | 什么值得记（决策/偏好/结果，不是每句话）、去重、冲突时谁赢、时效（TTL）、用户可查可删 |
| 读的优先级 | **结构化 typed getter 优先**（按 user_id 取偏好），语义搜索只作兜底——语义搜索会漏、会串 |
| 摘要 vs 原文 | 摘要进上下文，原文留在库里按需回取（带引用） |
| 隔离 | tenant/user namespace 全链路；cache key 带租户前缀；向量库分 namespace |

**④ 边界与代价**
- **记忆污染**：一次错误的推断被写进长期记忆，之后每次回答都带着它，且很难发现。
- 隐私与合规：记了不该记的（PII/密钥）比不记更危险；必须有删除与导出能力。
- 噪声：记忆越多，召回越差——需要定期归档/衰减。
- 记忆不是检索：检索找"文档里说了什么"，记忆找"我们之前发生过什么"，别混用同一套打分。

**⑥ 面试追问（三层）**
1. **怎么衡量**：跨会话任务完成率、重复询问率、记忆命中率、错误记忆率（记错的比例）、上下文里记忆的 token 占比。
2. **为什么不用另一方案**：为什么不做成"把历史全塞进长窗口"？→ 成本、context rot、无隔离。为什么不全用向量检索？→ 结构化事实用查表更准更快。
3. **线上坏了怎么定位**：先查"错误记忆"（谁写进去的、什么时候写的）→ 再查隔离（是否串用户）→ 最后查召回（该记的没记/该忘的还记着）。
