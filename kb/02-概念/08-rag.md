# RAG：十段链路，最常断在解析、权限、版本三处

**① 一句话定义**
把外部知识**检索出来再交给模型**，让回答有依据、可更新、可引用、可鉴权——本质是把"记忆"从模型参数里搬到你的数据库里。

**② 它解决什么问题**
模型有知识截止日期、不知道你的私有数据、没有出处、会编。微调能灌知识但不擅长"频繁更新的、需要精确引用的、需要按权限过滤的事实"。RAG 用检索解决了这三点。

**③ 关键机制（十段链路，每段的失败都会伪装成"模型不行"）**

```
采集 → 解析 → 切分 → 向量化 → 索引(+ACL) → 查询改写 → 召回 → 融合/重排 → 上下文拼装 → 生成+引用
```

| 段 | 关键决策 | 常见断点 |
|---|---|---|
| 采集 | 增量同步、删除传播（tombstone）、失败重试 | 删了的文档还在被引用 |
| 解析 | PDF/表格/图片/代码的结构保留 | **表格被拍平、标题层级丢失** → 检索到也对不齐 |
| 切分 | 按结构切（标题/段落/函数）+ 递归兜底 + 10–20% overlap | 切在语义中间；块太大稀释相似度、太小丢上下文 |
| 向量化 | 模型选择、维度、多语言 | 换模型不重灌 → **混版本，质量静默下降**（P8） |
| 索引/ACL | **权限必须下推到检索**（namespace/过滤条件），不要后过滤 | 先取 top-k 再过滤 → 有权限的全被滤空（P7） |
| 查询改写 | 多轮、同义扩展、HyDE、拆子问题 | 用户问"它"，系统不知道"它"指什么 |
| 召回 | top-k、混合检索 | 召不回 → 后面全是幻觉 |
| 融合/重排 | RRF/加权 + cross-encoder（详见 [09-检索与重排](09-检索与重排.md)） | 好块被排到 20 名外 |
| 拼装 | 顺序、去重、长度预算、出处标注 | 同类文档重复 5 份挤爆窗口 |
| 生成 | 引用 docId/span、**允许说"不知道"** | 没依据也硬答（幻觉 + 编引用） |

**七类失效点**（论文归纳 + 生产复盘）：库里没有 ／ top-k 没召回 ／ 召回但被截断 ／ 抽取拼接失败 ／ 格式错 ／ 粒度不对 ／ 答案不完整（跨文档多跳）。
再补三个工程向的：**权限、过期索引、embedding 混版本**。

**④ 边界与代价**
- 库里没有的，RAG 不会变出来 → **"无答案"必须是一等公民**（abstain + 引导提问），否则模型会编。
- 引用正确 ≠ 内容正确：模型可能引用对了段落却总结错 → 评测要看 faithfulness。
- 多跳推理差：需要迭代检索（retrieve → 读出线索 → 再检索）。
- 成本不在检索，在**上下文长度**：召回 20 条全塞进去，又贵又糊。

**⑤ 工程落点**
- `projects/_template/src/tools/builtin.ts` 的 `search_docs` —— 最小 RAG 的"检索段"：关键词打分 + **检索期 ACL 过滤** + 返回 `docId` 与 `span`
- P2 项目补齐：解析器、切分器、embedding、向量库、rerank、评测集
- 观测：每段打点（召回条数、召回分数、拼装后 token、引用命中率）

**⑥ 面试追问（三层）**
1. **怎么衡量**：检索侧 recall@k / hit rate / MRR；生成侧 faithfulness、citation 准确率、abstain 正确率；端到端任务成功率 + 置信区间。
2. **为什么不用另一方案**：为什么不上微调？→ 知识会变、要引用、要按权限过滤。为什么不把整个知识库塞进长上下文？→ 成本 + context rot + 无法鉴权。
3. **线上坏了怎么定位**：先判"答案在不在 top-k 里"（判检索责任还是生成责任），再查索引版本/新增删除，再查 query 分布漂移，最后才动 prompt。
