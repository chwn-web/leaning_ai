# 可观测与成本：没有 trace 就没有排障，没有拆账就没有降本

**① 一句话定义**
让每一次 LLM 调用、每一次工具执行**可追溯**（span/trace），并让每一分钱、每一毫秒**可归因**（token/成本/延迟按维度拆开）。

**② 它解决什么问题**
Agent 是黑盒：同样输入可能走不同路径，线上"变差了"你没法复现。账单突增时，如果只有一个总数，你连"是输入变长还是调用变多"都不知道。

**③ 关键机制**

**① 三类 span（最小可观测集）**

| span | 必带属性 |
|---|---|
| `llm` | model、input/output tokens、cost、TTFT、finishReason |
| `tool` | toolName、参数摘要（脱敏）、耗时、ok/errorKind |
| `step` | 第几步、本轮调用了几个工具、上下文 token |

全部带 `traceId / spanId / parentSpanId / sessionId / tenantId`——**没有 traceId 串起来的多 agent 等于没监控**。

**② 四组指标（对应四类角色的问题）**

| 组 | 指标 | 谁在看 |
|---|---|---|
| 任务 | 成功率（pass^k）、平均步数、循环率、人工接管率 | 产品/你 |
| 模型 | token 用量、成本、TTFT、p95 延迟 | 你 |
| 工具 | 成功率、校验失败率、超时率、重试次数 | 你 |
| 体验 | 首次反馈时间、中断率、重试点击率 | 前端/产品 |

**③ 成本三本账 + 五个杠杆**

```
总成本 = 输入 token × 单价 + 输出 token × 单价 − 缓存命中折扣
```
- 杠杆 1：**路由到小模型**（真实案例：70% 调用迁到小模型，在 3.2 倍负载下月成本从 $14,200 降到 $6,800）
- 杠杆 2：**prefix cache**（稳定前缀放前面，命中直接省钱又降 TTFT）
- 杠杆 3：截断/摘要/精准检索（别把 20 条文档全塞进去）
- 杠杆 4：`max_tokens` 与早停
- 杠杆 5：**每任务预算守卫**（`budget.spend()` 超限就停，而不是等账单）

**④ 边界与代价**
- 日志里有 PII 与密钥 → 必须脱敏，且要能按租户删除。
- trace 全量存很贵 → 采样（错误全存、成功按比例）+ 保留期。
- 指标太多没人看 → 每周只出"前 3 类失败 + 成本环比"。

**⑤ 工程落点**
- `projects/_template/src/obs/tracer.ts` —— span 生成、JSONL 落盘、`summary()`（llm/tool 次数、token、成本、总耗时）
- `projects/_template/src/core/budget.ts` —— 成本与步数预算，超限抛 `AppError("budget")` 由循环优雅退出
- 练习：跑 `node src/main.ts` 后打开 `data/traces/*.jsonl`，数一数一次任务产生几个 span、哪一层的耗时最大

**⑥ 面试追问（三层）**
1. **怎么衡量**：上面四组指标 + 每任务成本分位（p50/p95），不是均值。
2. **为什么不用另一方案**：为什么不用现成 APM？→ 能接，但要补 LLM 语义字段（token/模型/工具）。为什么不做全量日志？→ 成本与合规。
3. **线上坏了怎么定位**：`traceId` 回放 → 看是"步数变多/单步变贵/工具变慢/重试变多" → 对应到具体层（见 [03-框架/02-排障四轴](../03-框架/02-排障四轴.md)）。
