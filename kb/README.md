# 知识库（KB）：把"看过"变成"能讲、能设计、能排障"

> 这个目录不是笔记堆，是**一套能被追问三层的知识地图**。
> 面试官不会考你"知不知道 RAG"，他会问"你的召回率怎么测的、为什么不用另一个方案、线上掉了 12 个点你怎么定位"。这三问对应下面三个层次。

## 0. 本仓库四个目录的分工（别混用）

| 目录 | 回答什么问题 | 什么时候看 |
|---|---|---|
| `plan/` | **我什么时候做什么、怎么算做完了** | 每周日开始排下周 |
| `kb/`（本目录） | **它是什么、为什么这么设计、坏了怎么修** | 学概念、写设计、面试前 |
| `projects/` | **代码长什么样、怎么跑起来** | 动手时 |
| `research/` | **证据在哪、数据出处** | 需要引用/怀疑结论时 |

一句话：**plan 管节奏，kb 管理解，projects 管证据，research 管出处。**

## 1. 三条使用路径

**路径 A：学一个新概念（W1–W24 每周都会走）**
`kb/01-全景图.md` 找到它属于哪一层 → 读对应 `kb/02-概念/*.md` → 去 `projects/_template` 里找到实现它的那个文件 → 合上文档，用自己的话复述一遍（卡住的地方就是没懂）。

**路径 B：接到一个需求/写一个设计**
`kb/03-框架/01-方案选型决策树.md` 先判"该不该用 Agent" → `kb/03-框架/04-设计文档模板.md` 填一页 → 对照 `kb/01-全景图.md` 检查七层有没有漏（**漏层 = 上线必炸**）。

**路径 C：出问题了（质量/慢了/贵了/挂了）**
`kb/03-框架/02-排障四轴.md` 先定轴 → 再看该层概念笔记的"常见故障"段 → 最后看 `plan/05-高频题库.md` 第 3 节的 16 个坑里有没有同款。

## 2. 笔记模板（所有 `02-概念/*.md` 必须这 6 段，缺一段不算写完）

```
① 一句话定义      —— 20 字内，说人话，不抄 Wiki
② 它解决什么问题  —— 没有它之前，人们怎么做，痛在哪
③ 关键机制        —— 3-6 条，每条要能推出一个工程约束
④ 边界与代价      —— 什么时候它不 work；用它要付出什么
⑤ 工程落点        —— 对应 projects/_template 的哪个文件、哪个函数
⑥ 面试追问        —— 三层：怎么衡量 / 为什么不用另一个 / 线上坏了怎么定位
```

**第 ④ 段是这条知识库里最值钱的部分。**只会说"RAG 好"的人满地都是，能说"RAG 在权限过滤、embedding 换版本、解析丢表格这三处最容易断"的人才值钱。

## 3. 索引维护规则（否则两周后这堆文件就废了）

- 任何新增笔记，**必须**在 `kb/00-索引.md` 的对应表里加一行（文件、一句话、挂哪周）。
- 一个概念如果在两篇里都讲，只留一处详解，另一处写"详见 …"——**不要复制粘贴**。
- 每篇 ≤ 80 行。超过就拆。笔记的价值在"能扫完"，不在"写得全"。
- 复制粘贴的原文不算笔记。要么删，要么改写成自己的话。

## 4. 复习机制（不复习 = 白写）

| 频率 | 动作 | 耗时 |
|---|---|---|
| 每周日 | 随机抽 2 篇概念笔记，合上后讲 3 分钟；讲不顺的标红 | 20 min |
| 每两周 | 重新手画一次 `kb/01-全景图.md` 的七层图（不看原文） | 15 min |
| 每月末 | 把 `kb/05-常见误解.md` 过一遍，看有没有新增的误解 | 10 min |

**判定"掌握"的唯一标准**：能在白板上画出七层，并说出任意两层之间的接口是什么、这一层挂了会怎样。

## 5. 怎么打开

这些是普通 Markdown，任何编辑器都能看。**推荐用 Obsidian 打开仓库根目录**（`D:\TCL\leaning_AI_agent`）：`[[双链]]` 不用改就有效，还能看到概念之间的图谱，比目录树更能暴露"你以为你懂了其实没连上"的地方。

本知识库内部统一用相对路径 Markdown 链接（在任何工具里都能点），需要图谱时在 Obsidian 里看重名文件即可。
