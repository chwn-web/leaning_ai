## 2. 高价值题（46 题，含回答骨架）

### A. LLM 基础与成本

**Q1 [高] 上下文窗口为什么贵？KV cache 怎么增长？**
① attention 随长度 O(n²)，KV cache 显存 O(n)；② 估算 ≈ 2×batch×layers×hidden×seq×字节（GQA 按 KV 头数再缩）；③ 7B/32 层/4K 已到 GB 级；④ MQA/GQA、PagedAttention、continuous batching 降本；⑤ 长上下文还有 lost-in-middle 的质量代价。

**Q2 [高] temperature=0 为什么不保证可复现？**
① T→0 趋近 argmax，但 top-p 截断仍在；② 浮点非结合、batch 组合、MoE 路由、并发都会让结果变；③ 评测必须固定模型版本/参数/seed 并多次取样；④ 温度不是"正确率旋钮"。

**Q3 [高] 微调 / RAG / Prompt 怎么选？**
① prompt 管行为与格式；② RAG 管外部事实、新鲜度、可引用；③ 微调管风格、格式、领域分布、小模型蒸馏，**不擅长注入可更新事实**；④ 顺序是 prompt→RAG→微调，用 eval 决定；⑤ 可组合。

**Q4 [高] 怎么给产品选模型？**
① 自建 100–300 条 golden 集，评成功率/格式/工具调用/成本/延迟；② 单测长上下文、中文、JSON、function calling；③ 简单请求小模型、难请求大模型做路由；④ 锁版本 + 回归；⑤ 公开榜只做初筛。

### B. 上下文工程

**Q9 [高] 上下文工程是什么？长对话怎么压缩？**
① 目标不是塞满窗口，而是把"对当前决策有用的信息"放对位置；② 分层：稳定规则 / 任务状态 / 工作笔记 / 检索证据；③ 摘要会丢归属、数字、引用 → 必须保留结构化事实；④ working notes / checkpoint 可省 40–60% token；⑤ 压缩后重放关键约束并做一致性校验。

**Q10 [高] 为什么长上下文在窗口内也会失效？**
① lost in the middle：首尾强、中间弱；② context rot：输入变长性能非均匀下降，主流模型都有；③ 干扰项与自相矛盾材料；④ 对策：关键指令放首尾、分段结构化、用检索替代堆砌；⑤ **必须在目标长度上做 eval**，只测短样本等于没测。

**Q11 [高] 怎么防提示注入？**
① 指令与数据分层（instruction hierarchy、分隔符、spotlighting）；② 不可信内容不得触发工具或外发；③ **lethal trifecta**：私有数据 + 不可信内容 + 外发通道同时具备即高危；④ 工具白名单、参数校验、不可逆操作人工确认；⑤ egress 限制、输出过滤、审计；⑥ **没有只靠 prompt 的完美防御**。

**Q12 [中] prompt caching 怎么用不出错？**
① 稳定前缀（system/tools/few-shot）放最前，动态内容放后；② cache key 含模型/版本/租户；③ 工具描述变更会让缓存失效，发布要预热；④ 看命中率、TTFT 与账单。

### C. 结构化输出与工具调用

**Q13 [高] 怎么拿到可靠的结构化输出？**
① JSON Schema / function calling / 约束解码；② **严格 JSON 只保证语法，不保证字段语义与事实**；③ 解析 → schema 校验 → 业务校验 → repair/带错误重问；④ 失败样本回流 eval；⑤ 流式场景先缓冲完整 JSON 再解析。

**Q14 [高] function calling 到底谁执行工具？**
① 模型只输出 tool name + JSON args，**不执行、也不保证参数合法**；② 运行时校验 → 执行 → 把结果回填为 observation；③ 支持并行调用与多轮；④ 工具错误要回填，让模型改计划。

**Q15 [高] 怎么设计工具？**
① 单 Agent 2–5 个工具，>10 个行为不稳；② 名称/描述/参数像给初级开发写 docstring；③ 枚举、格式、边界、示例写清；④ 绝对路径、分页、幂等、错误可读；⑤ poka-yoke，让参数难传错；⑥ **工具结果当不可信数据**。

### D. Agent 架构

**Q16 [高] Agent 和 workflow 的区别？什么时候不该用 Agent？**
① workflow 走预定义代码路径，Agent 由模型动态决定步骤与工具；② Agent 增量 = 循环 + 工具 + 状态，代价是成本/延迟/错误累积；③ **不该用**：路径固定、单次检索够、成本延迟敏感、不可逆且无审核、无法 eval；④ 先做最简方案，复杂度只在可证明提升时加。

**Q17 [高] ReAct vs Plan-and-Execute 怎么选？**
① ReAct 交错 thought/action/observation，灵活但短视；② Plan 先分解再执行，适合长任务/可并行，但必须能 replan；③ 混合：高层 plan + 低层 ReAct；④ 用成功率/步数/成本评。

**Q18 [高] 单 loop / planner-executor / 多智能体怎么选？**
① 单 loop 适合工具少、路径短；② planner-executor 适合可分解长任务；③ 多 Agent 只在**上下文隔离 / 并行 / 独立验证**时值得；④ 多 Agent 的失败多来自协调而非能力，互相同意 ≠ 已验证；⑤ **2–3 个 specialist 常是甜点，5 个更差更贵**。

**Q19 [高] 怎么做跨会话记忆又不炸上下文、不串用户？**
① 分 working / episodic / semantic；② 结构化事实用 typed getter，别盲做语义搜索；③ 写入策略、去重、冲突、时效；④ 租户隔离、删除、用户同意；⑤ 上下文只带摘要 + 按需检索。

**Q20 [高] 长任务里 Agent 死循环怎么办？**
① 最大步数/时间/花费；② 状态哈希、动作去重、无进展检测；③ 每步要求可验证进展；④ replan / 换策略 / 降级 / 人工；⑤ 离线用轨迹评循环率、步数、成本。

**Q21 [高] 工具报错和部分失败怎么处理？**
① 错误分类：瞬时/永久/策略/权限；② 退避重试 + 抖动，限次数；③ 非幂等先查后重试或上幂等键；④ 失败作为 observation 让模型改计划；⑤ 死信 / 人工接管 / 审计。

**Q22 [高] Agent 跑到一半失败但已经产生真实副作用，怎么保安全？**
① 副作用幂等 / 可补偿（saga）；② checkpoint + resume；③ 不可逆操作人工确认；④ 失败隔离与重放；⑤ 用 **pass^k**（k 次都成功）而不是 pass@k 评估；⑥ 监控、告警、回滚。

### E. MCP 与安全

**Q23 [高] MCP 是什么？为什么不直接用 function calling？**
① JSON-RPC 2.0，host/client/server，client 与 server 1:1；② 服务端原语 tools/resources/prompts，客户端 sampling/roots/elicitation；③ 传输 stdio / Streamable HTTP；④ 初始化做能力协商；⑤ **MCP 标准化发现/传输/鉴权，function calling 是模型输出协议，可叠加不是替代**。

**Q24 [高] 把内部 API 通过 MCP 暴露给模型，怎么设计才安全？**
① OAuth 2.1，token 绑定 audience，**禁止 token passthrough**；② 最小 scope、逐步提权；③ 每工具参数校验，只读优先，写操作审批；④ 审计/限流/租户隔离；⑤ **不信任 tool description 与返回结果**。

**Q25 [高] MCP tool poisoning 是什么？怎么防？**
① 恶意 server 在 tool description 里藏指令，诱导读密钥/外发；② rug pull：批准后悄悄改工具；③ 固定版本/哈希，工具清单变更告警；④ 只装可信 server、跑在沙箱；⑤ 最小权限 + egress 限制。

### F. RAG

**Q26 [高] 走一遍 RAG 全链路，并说出它通常在哪断。**
① 采集/解析→切分→embedding→索引→query 改写→召回→融合→rerank→组装→生成→引用；② 常见断点：解析丢表格、切分断语义、embedding 域不匹配、召回漏、rerank 错杀、上下文稀释、生成不忠实；③ 每段留指标；④ **先判定"答案在不在 top-k"，再分检索责任还是生成责任**。

**Q27 [高] 怎么切分？怎么知道切得好？**
① 按标题/段落/代码函数等结构切，递归兜底，10–20% overlap；② 小块检索 + 父块/邻块扩展；③ 保留标题、页码、表格、ACL 等 metadata；④ **用端到端正确率 + recall@k 比较方案**，不看 chunk 是否"漂亮"；⑤ 不同文档类型分别调。

**Q28 [高] 混合检索每一层各救什么？**
① 向量与 BM25 各取 100–200；② RRF/加权融合；③ cross-encoder rerank 20–50 条；④ **BM25 救精确词/ID，向量救语义，rerank 救排序**；⑤ rerank 救不了没召回的（召回是天花板），相似度分数不等于正确率；⑥ 设延迟预算与降级。

**Q29 [高] 检索和生成怎么分开评？**
① 标注 query→相关 passage；② 检索看 recall@k / hit / MRR / nDCG；③ 生成看 faithfulness / correctness / citation；④ 先看答案在不在 top-k，再判生成；⑤ 线上看命中率、无引用回答占比、bad case 回流。

**Q30 [高] RAG 常见失败模式有哪些？**
① 库里没有；② top-k 没召回；③ 召回但没进上下文/被截断；④ 抽取失败；⑤ 格式错；⑥ 粒度不对；⑦ 答案不完整；⑧ 权限、过期索引、embedding 混版本、材料自相矛盾。

**Q31 [高] 线上 RAG 一周掉 12 个点，没人改过 prompt，怎么排查？**
① 先看数据/索引：新文档、删除、解析失败、embedding 版本；② 拆检索/生成指标；③ 看 query 分布漂移与租户差异；④ 看模型版本、温度、上下文长度；⑤ **回放 trace + bad case，别先改 prompt**。

**Q32 [高] 千万文档 + 每人权限不同，怎么保证不越权？**
① **索引侧 ACL/tenant namespace 预过滤**，不要先取 top-k 再后过滤（会把结果滤空）；② 增量同步 + 删除 tombstone；③ 分片/副本/缓存；④ 引用与审计；⑤ 权限泄漏红队测试。

### G. 评测

**Q33 [高] 上线前怎么评一个 RAG/Agent 系统？**
① 100–400 条分层 golden，冻结版本；② 检索 recall@k + 生成 faithfulness/correctness/citation；③ LLM judge + 人工校准；④ 红线/abstain/权限用例；⑤ CI gate + 灰度。

**Q34 [高] LLM-as-judge 有哪些偏差？怎么缓解？**
① 位置偏差→随机换位；② 冗长偏差→长度校正；③ 自我偏好→多模型陪审；④ 温度>0 不一致→多次投票；⑤ 格式偏差→贴合训练格式；⑥ 对部分幻觉识别差，别用于细粒度事实判定。

**Q35 [高] 怎么让评测可复现？**
① 固定模型版本/温度/seed/工具 mock；② 缓存输出、记录 trace；③ 数据集版本化、去污染；④ judge 版本固定 + 人工抽检；⑤ **报置信区间：100 条约 ±8 分，400 条约 ±4 分**。

**Q36 [高] 测试集 70% 成功率，能上线吗？**
① pass@k 是"至少一次成功"，pass^k 是"k 次都成功"，生产看 pass^k；② 5% 单步失败在长链路会复利；③ 按任务风险定阈值；④ 报分布而非均值。

**Q37 [高] Agent 的轨迹怎么评（不只看最终答案）？**
① 工具选择/参数正确率；② 步数/成本/循环率；③ 中间证据与引用；④ LLM judge + 规则 + 人工抽样；⑤ 失败分类。

**Q38 [高] Agent 要 trace 什么？**
① 每次 LLM/tool/retrieval 一个 span；② 输入/输出/token/成本/延迟/错误；③ 会话/任务/trace id；④ PII 脱敏与采样；⑤ 可回放、可对比；⑥ 告警：错误率、p95、成本、循环。

### H. 工程化

**Q39 [高] 30 秒的 Agent 工作流，流式 UX 怎么设计？中途失败怎么办？**
① SSE/WebSocket，事件分 status/token/tool/error；② 先出计划与进度，降低焦虑；③ **工具参数不要混进正文**；④ 断线可恢复、幂等；⑤ 失败给可重试或部分结果；⑥ 背压与取消。

**Q40 [高] 超时和重试怎么设？**
① 连接/读/总超时分开；② 指数退避 + 抖动；③ 重试预算、熔断；④ 非幂等不盲重试；⑤ **超时不等于业务未发生**；⑥ 死信与告警。

**Q41 [高] 10 路并发正常，50 路就崩，为什么？**
① 连接池/事件循环阻塞；② 供应商 rate limit 与配额；③ 内存与上下文膨胀；④ 共享状态、缓存击穿；⑤ 队列 + 背压 + 每租户限流；⑥ 压测到 p95。

**Q42 [高] 怎么控 token 成本？**
① 拆输入/输出/缓存三本账；② 路由到小模型；③ 截断/摘要/检索；④ prefix cache；⑤ max_tokens 与早停；⑥ 每任务预算 + 告警。

**Q43 [高] 多租户怎么防数据泄漏？**
① tenant_id 全链路；② 向量 namespace / ACL；③ cache key 前缀；④ 日志与评测隔离；⑤ 密钥/KMS；⑥ 删除与导出；⑦ 越权测试。

### I. 系统设计（W23 白板练）

**Q44 [高] 设计企业知识库 Agent** —— 连接器与增量同步 / 解析 / 切分与 ACL / hybrid+rerank+引用 / 权限过滤 / eval 与观测 / 无答案时 abstain。

**Q45 [高] 设计能操作浏览器的 Agent** —— 感知（DOM/a11y+截图）/ 动作空间与元素定位 / 等待校验重试 / 沙箱与凭据注入 / 不可逆操作确认 / 轨迹回放与 eval / 人工接管。

**Q46 [高] 设计多租户 Agent 平台** —— 控制面/数据面分离 / 租户隔离（prompt、vector、cache、eval）/ 工具网关与权限 / 配额计费 / 可观测审计 / 版本灰度 / 数据删除。

| P9 流式与工具调用冲突 | 工具参数被当正文吐给用户 | **P1** | 分离 text/tool_call 事件 + 缓冲完整参数 + 先发状态再发正文 |
| P10 JSON 正确≠语义正确 | 字段缺失/枚举错/事实错 | **P1/P2** | schema + 业务校验 + repair + 单测覆盖边界 |
