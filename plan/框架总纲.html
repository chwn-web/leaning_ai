③ 七层结构（点每一层看要点）

L6 体验层
流式渲染、中断、人工审批、错误态
要点：首字延迟是体验第一指标 ｜ 流式过程要能让用户中断 ｜ 写操作必须人工确认 ｜ 幂等键从这里传下去，不能让模型自己编 ｜ 失败态要给出可执行的下一步。
L5 编排层
循环、工具选择、预算、多 Agent
要点：模型→工具→观察→再模型的最小循环 ｜ 死循环检测靠动作签名不是步数 ｜ 步数/成本/墙钟三重预算前置检查 ｜ 单 Agent 工具数 2–5，>10 明显不稳 ｜ 多 Agent 协调失败率约 79%，2–3 个 specialist 是甜点。
L4 上下文层
提示分层、压缩、记忆、检索拼接
要点：系统提示/工具/历史/检索/输入的预算与丢弃顺序 ｜ 前缀稳定才能吃 prompt cache ｜ 压缩会腐化（越压越丢约束） ｜ working notes 省 40–60% token ｜ 权限过滤必须下推到 L1。
L3 模型层
采样、结构化输出、FC 协议、降级
要点：token 与成本能口算 ｜ temp=0 也不可复现的四个原因 ｜ 严格 JSON 只保语法不保语义 ｜ 解析失败要多级降级 ｜ 换小模型/微调/加规则的判断依据。
L2 工具层
schema、校验、错误分类、幂等、MCP
要点：工具失败返回 ok:false 而不是抛异常 ｜ 参数一律当不可信输入 ｜ 幂等键由调用方传 ｜ 超时≠没发生 ｜ MCP = JSON-RPC 2.0 + OAuth2.1 + 禁 token passthrough ｜ 与 Function Calling 是叠加不是替代。
L1 数据层
解析、切分、embedding、检索、重排
要点：召回是天花板，先量 recall@k ｜ BM25 救精确词、向量救语义、rerank 救排序 ｜ 权限 ACL 在索引侧预过滤（后过滤会滤空） ｜ 换 embedding 必须全量重灌 ｜ 无答案识别比硬编答案重要。
L0 横切
评测、trace、成本、安全
要点：评测集来源要写清 ｜ pass@k 看能力、pass^k 看生产稳定性 ｜ 20 条 95% 的置信区间是 76%–99% ｜ 判定器自己也会写错（假绿） ｜ lethal trifecta 砍一条即降险 ｜ 重试风暴与成本失控的熔断。
