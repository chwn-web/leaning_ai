## 1. 投递门槛（达不到就别投，浪费机会）

三条全满足再开投：

- [ ] 有一个**已上线**的 Agent 产品，能打开 URL，至少有真实用户
- [ ] 有一个项目带**量化数据**（"提升 27%"这种，不是"接入 RAG"）
- [ ] 能白板画出任意一个项目的完整架构 + 失败兜底，并讲清 3 个 trade-off

**自测方法**：找 1 个不做 AI 的朋友，你讲 5 分钟，让他复述。他复述不出"你解决了什么问题"，就是没准备好。

## 2. 简历模板

**结构（一页，最多两页）**
> 调研结论：简历顺序应为 **定位 → 代表作 → 信任状**，技术栈放最后。技术栈清单放前面会被判"技术流水账"。

```
姓名 | 城市 | 电话 | 邮箱 | GitHub | 作品集
求职意向：AI Agent 工程师 / LLM 应用工程师

① 定位（3 行）
X 年全栈（前端为主）经验，主导从 0 到 1 落地 N 个 LLM/Agent 系统，
擅长把 Agent 做成可用产品（流式交互、过程可视化、人工审批），
具备 RAG 全链路与自建评测体系经验。目前在做 XX（一句话说明你在 AI 上投入了多久）。

② 代表作（3 个项目，每个 4–6 行，用"四件套"）
项目名｜角色｜时间｜链接
   - 场景：谁的什么痛（1 行）
   - 关键决策与权衡：技术上最难的一点 + 为什么选 A 不选 B（2 行）
   - 可验证结果：数字（1–2 行）
   - 技术栈：一行关键词

③ 工作经历（弱化与 AI 无关的细节，突出工程能力、复杂系统、跨团队）
④ 开源 / 博客 / 演讲（技术写作在 JD 里算产出，别省略）
⑤ 专业技能（只写能扛住追问的，5 行内）
⑥ 教育
```

**每个 bullet 的"四件套"**：场景 → 职责 → 关键决策与权衡 → 可验证结果。
缺任何一项，面试官就会问"所以呢"。反面例子：「使用 LangGraph 实现多智能体协作」——没有场景、没有代价、没有结果。

**你的第 1 个代表作已经现成了**：TCL 审核平台的"AI 自动审核 + 自然语言取数"。它比课程项目值钱得多——真实用户、真实误判代价、真实权限与审计。**但必须脱敏**（写"某光伏制造企业"，不写客户名与单据内容），素材与待补数字见 [`notes/我的素材.md`](../notes/我的素材.md)。三个代表作的建议排序：
1. 现职 AI 审核链路（脱敏）——证明你真跑过，且懂判定标准与兜底
2. P2 知识库 Agent + 评测体系——证明你会用量化证明效果
3. P3 编排平台 / P4 审核类垂直产品——证明你能独立交付一个完整系统

**写简历的 6 条硬规则**
1. 动词开头，去掉"负责/参与"。
2. 每个 bullet 必须能回答"所以呢"——没有结果的技术描述等于没写。
3. 数字优先：延迟、成本、准确率、用户数、节省工时。
4. 不写"熟悉/了解"超过 3 项；写了就要能被追问 3 层。
5. 项目按"最相关 + 最有结果"排序，不按时间。
6. 投不同岗位准备 2 个版本：偏应用（突出产品与全栈）、偏平台（突出架构与工程化）。

## 3. 投递策略

| 批次 | 时间 | 数量 | 目的 |
|---|---|---|---|
| 试水 | 3 月中（W18） | 5–8 家 | 拿真实反馈，不指望结果；暴露问题 |
| 主攻 | 4 月底–6 月 | 30–50 家 | 正式战役 |
| 补漏 | 7–8 月 | 10–20 家 | 捡漏 + 谈更好的 offer |

**渠道优先级**
1. 内推（成功率最高）：找前同事、技术社区、开源项目 maintainer
2. 公司官网/招聘页直投（AI 创业公司通常官网就有）
3. BOSS 直聘 / 脉脉（响应快，适合中小公司）
4. 猎头（3 年以上经验可以用了）
5. 招聘网站海投（最低效，最后做）

**筛选公司的 5 个问题**（面试时反问）
1. 这个 Agent 现在的线上指标是什么？失败时怎么兜底？
2. 团队里谁负责评测？评测集谁维护？
3. 模型是自研还是调 API？成本占收入多少？
4. 这个岗位前 3 个月要交付什么？
5. 上一任/同岗位的人现在在做什么？

> 答不出 1、2 的公司，大概率是"套壳 + 没工程"，去了学不到东西。

## 4. 面试流程与应对

典型 4 轮：

| 轮次 | 考察 | 准备重点 |
|---|---|---|
| 1 技术初面 | 项目深挖 + 基础概念 | STAR 讲法 + 题库八股 |
| 2 技术二面 | 系统设计 / 手写 Agent 代码 | 白板框架 + 现场写循环 |
| 3 交叉/主管面 | 判断力、trade-off、协作 | 失败案例、决策复盘 |
| 4 HR | 动机、稳定性、薪资 | 转岗动机故事、期望区间 |

### 4.1 项目深挖（必被问的 12 个问题）

1. 这个项目解决谁的什么问题？你怎么验证需求真实？
2. 为什么用 Agent 而不是规则/普通自动化？
3. 架构画一下，请求链路是什么？
4. 最难的技术点是什么，你怎么解决的？
5. 效果怎么衡量？指标怎么定义的？
6. 失败率多少？失败主要分几类？
7. 成本和延迟多少？怎么优化的？
8. 如果用户量涨 100 倍，哪里会先崩？
9. 你做过哪些被你否掉的方案？为什么否？
10. 如果重来一次，你会怎么改？
11. 安全怎么做的？如果有人往文档里塞指令怎么办？
12. 这个项目里你独立做了多少？别人做了什么？

### 4.2 系统设计白板框架（背下来）

```
1. 澄清（2 分钟）：用户是谁、规模、延迟/成本约束、成功标准
2. 接口（1 分钟）：输入输出、同步/异步、流式与否
3. 高层架构（5 分钟）：接入层 / 编排层 / 工具层 / 检索层 / 存储 / 可观测
4. 数据流（3 分钟）：一次请求走一遍，标出每一步的失败点
5. 关键设计（10 分钟）：挑 2 个深挖——上下文管理、工具失败恢复、评测
6. 兜底与演进（3 分钟）：限流、降级、灰度、成本上限
7. 主动 trade-off（2 分钟）：我选了 A 不选 B，因为…
```

**常考 6 题**：企业知识库 Agent / 浏览器操作 Agent / 客服工单 Agent / 代码 Review Agent / 多租户 Agent 平台 / Agent 的评测系统。

### 4.3 转岗动机（必问，准备 90 秒版本）

要讲成"能力延续"而不是"逃离前端"。**你的版本（拿现职讲，比通用模板强得多）**：

> 我在 TCL 做审核平台，前端为主。产品开始上 AI 自动审核以后，我发现真正难的不是把模型接进来，而是三件事：判定标准怎么从人的口径变成系统能执行的东西、判错了谁负责、怎么证明这下比人审得好。这三件事我天天在跟业务和运营吵，也就在这个过程里把手从界面伸到了链路里——接模型、做取数、做评测对比。我现在最强的不是模型本身，而是把不确定的模型能力包装成用户敢用的产品，这正好是 Agent 工程师最缺的那一环。

要讲成"能力延续"而不是"逃离前端"（通用版，方向一致时可用）：
> 我做前端这些年，最耗时的是把需求翻译成界面逻辑；LLM 出现后我发现这类"翻译"能被 Agent 接管，于是从做接口对接开始，逐步做了 X、Y、Z。我发现自己最强的不是模型本身，而是把不确定的模型能力包装成用户敢用的产品——这正好是 Agent 工程师最缺的一环。

**不要说的话**：前端没前途 / AI 是风口我想赚钱 / 我看了很多课 / 我公司也在做 AI 所以我懂（要说你**具体做了什么**，不蹭公司）。

### 4.3b CTO 面四连问（一面二面过完才会遇到，但答不好直接砍 offer）

> 来自一手面经（`plan/05` §4.1 的 T024–T031）：走到第三轮的候选人技术差距已经不大，**CTO 面只判断三件事——你是不是真信这个方向、你和别人差在哪、把你放上去能不能自己把事做成**。

| 问 | 他们真正在听什么 | 你的答法骨架（写出来，别临场编） |
|---|---|---|
| **为什么选 Agent？是跟风还是长期？** | **时间证据**，不是热情形容词 | "我在 2025 年 X 月就开始做 X（有仓库/时间戳），当时是为了解决 Y；现在做的 P1/P2 是当时那条线的延续" + 一句你对方向的判断 |
| **你和别的候选人差异是什么？** | 一句话定位，且能被上面的证据支撑 | "多数人是会调模型，我是把模型能力做成敢上线的产品——我有评测集、trace、成本看板和一次完整的回滚经历" |
| **你能给公司创造什么价值？** | 你有没有**真实落地**过，以及能不能迁移 | 一个项目讲四件套（问题 → 关键决策与权衡 → 可验证结果 → **如果做到你们业务，我会先动哪一步**） |
| **给你一个运营/独立负责一个方向，能做到头部吗？** | 你是在等任务还是在找问题 | 先反问目标与资源，再给 90 天计划：第 1 个月补评测基线，第 2 个月定 3 个可量化指标，第 3 个月做一个能上线的闭环；明确说出最可能失败的点 |

**准备纪律**：W24 前把 4 段答案各写成 200 字并背下来；每段必须含**一个具体时间点**和**一个可验证的数字**，否则就是空话。

### 4.4 反问环节（准备 3 个）

- 这个岗位半年后"做得好"是什么样子？
- 团队现在最大的技术债是什么？
- 评测和线上监控目前是怎么做的？

## 5. 谈薪

- 先问区间，不先报数字："这个岗位的预算区间是多少？"
- 用总包对比：base + 奖金 + 期权（问清行权价、成熟期、回购条款）+ 补贴
- 创业公司期权要打折看：问"上一轮估值、期权占总股本比例、回购政策"
- 有多个 offer 时，用"时间线"施压而不是"对赌"："我下周三前需要答复，另一家已经给了"
- 涨幅预期：转岗首份工作，**优先选能学到东西的团队**，其次才是薪资。第一份 Agent 工作的履历价值 > 短期 20% 差价。

## 7. 被拒后的处理

- 24h 内要反馈："方便说下这次主要差在哪吗？"（30% 的面试官会告诉你）
- 连续 5 家拒在同一环节 → 那个环节就是短板，停下投递补 2 周
- 不要因为 1 家拒就改简历；3 家拒在同一处才改
