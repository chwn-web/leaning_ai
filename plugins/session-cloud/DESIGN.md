# 会话级「仅本机 / 云同步」开关 —— 设计稿 v0.1

> 参考：用户截图里 Cursor/Codehub 的 `Continue on` 菜单（Cloud ↔ This PC）。
> 差异：那个是"在哪台执行"，我们要的是**这条会话的数据存放在哪**——本机磁盘，还是云端。
> 本文只做设计，不写实现。确认后按 §9 里程碑开工。

## 1. 一句话

给**每一条会话**加一个开关：`仅本机`（默认）或 `云同步`。选云同步后，这条会话的全部内容（消息、工具调用、附件、标题、模型、工作区名）上传到你以为的云端；换电脑、重装系统后能把整条会话拉回来接着聊。

## 2. 用户故事

1. 我在公司电脑问了一堆 TCL 审核平台的问题，想回家接着问 → 在会话右上角切成「云同步」，回家打开 DSH，会话列表里就有它。
2. 我这台要重置 → 只要在云同步状态的会话都能 `pull` 回来，不用手工拷目录。
3. 公司私密项目的会话 → 保持「仅本机」，任何字段都不出本机（默认值即安全值）。
4. 我不想每条都点 → 可以在设置里选"新会话默认仅本机 / 默认云同步"，但**默认必须是仅本机**。

## 3. 交互（对齐截图的心智）

会话页头右侧一个 chip，点开是一个两项菜单：

```
┌───────────────────────────────────────────────┐
│  TCL 审核平台 Agent 学习          [🖥 仅本机 ▾] │   ← conversation.session.header.actions
├───────────────────────────────────────────────┤
│  ……消息流……                                   │
│                                               │
│  +  [输入框]                      模型 ▾  ▶   │
└───────────────────────────────────────────────┘

点开 ▾：
┌──────────────────────────┐
│ 存储位置                  │
│ ☁ 云同步                  │  ← 选中后：上传全部历史 + 之后每轮增量推送
│   已同步 2 分钟前 · 3.2 MB │
│ ──────────────────────── │
│ 🖥 仅本机（默认）          │  ← 切回：停止同步；询问云上那份是否保留
└──────────────────────────┘
```

首次切到「云同步」弹一次确认（`shell.overlay`）：

```
将上传「TCL 审核平台 Agent 学习」
  · 128 条消息 / 14 次工具调用
  · 3 个附件（1.2 MB）
  · 标题、模型、工作区名
合计约 3.2 MB → 云端存储 `dsh-sessions`（私有）
[ ] 以后同类会话不再询问     [取消]  [上传]
```

复制几处细节：

- chip 有四种外观：`仅本机`（灰）、`同步中…`（转圈）、`已同步 2 分钟前`（绿）、`同步失败`（红，点开看原因）。
- 同步失败**不影响对话**，只是不传；重试是显式的"立即重试"。
- 页头只是主入口，会话行右键菜单（`sidebar.workspaces.session.menu.item`）同步提供同一开关。

## 4. 状态机（每条会话一份）

```
                 ┌──────────┐  选中云同步+确认   ┌────────────┐
                 │  local   │ ────────────────▶ │ uploading  │
                 └──────────┘                   └─────┬──────┘
                      ▲                               │ 成功
        切回本机/取消  │                               ▼
                 ┌────┴─────┐     turn/end          ┌──────────┐
                 │ disabled │ ◀──── 失败 ───────────│  synced  │
                 └──────────┘                      └────┬─────┘
                                                       │ 新一轮开始
                                                       ▼
                                                  ┌──────────┐
                                                  │ syncing  │  ← 增量推送（只追加）
                                                  └──────────┘
```

不变量：

- **未闭合的 turn 不上传**（没有 `turn/end` 的日志可能是崩溃现场，传上去等于发一个截断快照）。
- **只追加**：会话日志是 append-only，所以正常情况下永远不需要"合并"；真分叉（两台机器同时写同一条会话）时两边都留，远端那份存成 `*.remote-fork-<ts>`，本地那份不动。
- **切回本机不删云上数据**，默认只停止同步；删除要二次确认（"云上那份保留 / 一并删除"）。

## 5. 云端存什么（数据面）

一条会话在云端是一个目录 / 一个前缀：

```
sessions/<workspaceKey>/<sessionId>/
  meta.json        # 标题、模型、工作区显示名、创建时间、最后活跃、事件数、字节数、sha256
  events.jsonl.zst # 会话事件流（harness 原生编码，按字节搬运，不解析）
  attachments/     # 被这条会话引用到的附件 blob（按 sha256 命名，跨会话去重）
  README.md        # （可选）给人看的摘要：多少条消息、涉及哪些文件
```

**关键决定：按字节搬运会话文件，不解析、不重编码。** 理由：会话格式是 harness 的私有约定（`session.v4.jsonl.zstd`，已经有 v0→v1→v2→v3→v4 的迁移史），插件解析再重建 = 每次 harness 升级就碎一次。字节搬运的风险只是"版本不匹配"，而这个错误是响亮可检测的（加载时 harness 自己会迁移或报错）。

`meta.json` 是我们自己的格式，只存**索引信息**，用于在没有本机文件的情况下也能画出会话列表（"云端有 3 条会话，本机没有"）。

## 6. 同步协议（v0.1 走 git，v0.3 可换对象存储）

底层就三个动作，任何后端都能实现：

| 动作 | 语义 | 幂等 |
|---|---|---|
| `upload(session)` | 把会话目录写进远端（首次全量） | 是（内容寻址 + 覆盖写） |
| `append(session, since)` | 把 `since` 之后的新事件追加进去 | 是（前缀合并检查） |
| `pull(session)` | 把远端会话落到本机会话仓 | 是（已存在且是前缀则跳过） |

**v0.1 用 git 私有仓库当后端**，原因：

- 零后端、零运维、零费用；鉴权复用用户已有的 SSH key；
- 天然有版本历史（等于免费"时光机"）；
- 现成插件（PerryLink / linbin）已经验证过这条路可行。

代价（要在 README 里写清）：zstd 二进制每次改动都是新 blob，仓库会膨胀；v0.2 加"按周 squash 历史"的清理。

`pull` 的落地动作要和 harness 对齐，两个硬点：

1. **cwd 改写**：会话事件里带工作区路径，本机没有该路径会挂不上。落地方案：按 `meta.workspaceName` 找本机同名工作区，命中就改写 cwd 后写入；没命中就留在"待放置"列表，用户在 UI 里点一下选一个工作区。
2. **投影缓存预热**：直接往持久化写入的会话，列表元数据不会自动出现，需要冷读一次（fail-soft）。

## 7. 平台落点（都是 DSH 已开放的缝，不改核心）

| 需要 | 用什么 | 证据（本机源码） |
|---|---|---|
| 页头 chip | `conversation.session.header.actions`（list, session） | `packages/client/ui-conversation/src/client/contract/slots.ts:63` |
| 输入区状态 chip（备选） | `conversation.input.left` / `conversation.composer.dock` | 同文件 `:179`、`:170` |
| 首次确认框 / 同步详情 | `shell.overlay`（list, root） | `packages/client/ui-layout/src/client/index.ts:83` |
| 会话行右键菜单 | `sidebar.workspaces.session.menu.item` | ui-sidebar 已注册 |
| 设置页（后端地址/加密/默认值） | `settings.section` | ui-settings 已注册 |
| 每会话状态持久化 | `ctx.storage.domain('session-cloud')` | `@deepseek-ai/dsh-storage-domain` |
| UI ↔ host 通信 | `ctx.webServer` 注册 `/_session-cloud/*` 路由 | 与 linbin 同route |
| 读写会话文件 | `ctx.sessionPersistence`（`loadStored`/`appendBatch`/`list`） | `@deepseek-ai/dsh-session-persistence` |
| 调 git | `ctx.subprocess` | 平台已有该服务 |
| 附件 | `@deepseek-ai/dsh-attachment` 的 blob 存储 | `~/.dsh/attachments/v1/objects` |

一条硬约束（决定架构）：**多会话列表/聚合是 host 侧的事**。UI 只拿投影（`useProjection`），不要在前端直接读文件；所有同步状态走 host 的 storage domain + 一条只读路由。

## 8. 安全与隐私（这个功能最容易翻车的地方）

1. **默认仅本机**。不装插件 / 不选云同步，一个字节都不出本机。
2. **上传前显示清单**（条数/附件/字节），不静默上传。
3. **传输**：git over SSH 或 HTTPS；v0.3 加端到端加密（age，密钥本机保管，云端只有密文）。
4. **凭据**：插件自己不存 token，复用用户 `~/.ssh` 或 git credential helper。
5. **仓库必须私有**。首次配置时如果检测到远端是公开仓库，直接拒绝并要求换成私有（GitHub API 一次探测即可）。
6. **删除语义明确**：切回本机 ≠ 删云端；删云端必须二次确认，并写一条本地审计记录。
7. **公司数据**：README 里明写"不要把含公司内部信息的会话设为云同步"，并在首次确认里给一句风险提示（不阻断，用户自己判断）。

## 9. 里程碑（每个都能独立验收）

**v0.1 最小闭环（≤3 天）**

- 设置页：git 远端、分支、加密开关（先只读展示）。
- 页头 chip + 两项菜单；切云同步 → 确认框 → 上传 → 变绿。
- 手动"立即同步"；失败显示原因。
- 验收：A 会话上传成功；`git log` 里能看到 `sessions/<...>/events.jsonl.zst`；切回本机后不再上传。

**v0.2 跨机可用（≤5 天）**

- turn/end 自动增量推送；未闭合 turn 跳过。
- 附件一起传（被引用的 blob）。
- 另一台：`pull` → 按工作区名匹配 → 待放置列表 → 投影预热。
- 验收：两台机器上同一条会话能互相接着聊，且历史一致。

**v0.3 可上架（≤5 天）**

- 端到端加密（age）；公开仓库检测；历史 squash 清理。
- 冲突可视化（双份 diff 提示）；离线重试队列。
- 五语 README、图标、locale、`engines.dsh` 声明、14 类测试（含"git 缺失""远端 403""日志损坏"三种失败面）。
- 上架材料：能力清单（`filesystem:read/write`、`network:egress`、`subprocess`）、隐私说明、诊断页（`doctor` 一键自检）。

## 10. 与现成插件的差异（为什么值得做）

| 现成插件 | 它的模型 | 我们的差异 |
|---|---|---|
| PerryLink `dsh-session-sync` | **整个 `sessions/` 目录**镜像进 git | 我们是**逐会话**选择；它把"公司项目 + 学习项目"全量上传，没法只传一条 |
| `@linbin-mk/dsh-session-sync` | **逐会话勾选**同步 | 它只有"同步/不同步"，没有"云"这个概念，也没有上传前的数据清单与体积预估 |
| 两个都不管 | —— | **附件**（`~/.dsh/attachments`）都不在同步范围；我们的 v0.2 必做 |
| 两个都要手工配 | —— | 我们做"换机向导"：clone → 落位 → 校验，一个按钮 |

## 11. 待你决定的三件事

1. **云端底座**：v0.1 用「私有 git 仓库」（零成本、可回滚）还是要直接上对象存储（OSS/S3，需要 AK/SK）？我建议先 git。
2. **入口位置**：放**会话页头右侧**（截图那种心智，推荐），还是放**输入框左下角**（跟截图的位置更像，但和模型选择器挤在一起）？
3. **加密**：v0.1 就先上端到端加密（多 2 天），还是 v0.3 再补（先跑通，但云端是明文）？

## 12. 不做的事（本设计明确排除）

- 不做"远程执行"（在云端跑 agent）。截图里那个 `Continue on: Cloud` 是执行位置，我们只做**数据位置**；两者可以以后叠加，但现在混在一起会把问题放大十倍。
- 不做团队共享 / 多用户权限。单人两机是 v1 的唯一场景。
- 不做会话内容的语义搜索（那是另一个功能，靠 `session-query`）。
