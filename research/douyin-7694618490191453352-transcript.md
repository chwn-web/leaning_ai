## 2. 修正后正文（按三轮拆开，我的措辞，不是逐字）

> 修正原则：只改能确定的名词与明显同音字，不改他的观点。凡是推断，加 `[ ]`。

### 开场

国庆第一天刚面完 MiniMax Agent 开发岗，太累了，在空调房都给我闷出汗了，顺便分享一下 Agent 的面试思路。我之前的项目细节有一部分是**包装**进去的[^1]。MiniMax 正常技术面是两轮，但我 base[^2] 已经 37K、本科两年薪资偏高，所以后面又加了一轮 CTO 面。三轮问的东西不一样，但**共同点只有一个：判断你到底有没有真的做过 Agent 系统**。

[^1]: 他原话就是"包装"，不是在自夸造假，后面他自己说"没有真跑过一面很容易被问穿"。
[^2]: base = 月薪 base。

现在 Agent 岗位的面试**大头在工程**：偏 RAG、Harness 工程、Agent 的评估、效果评测与策略迭代。

### 技术一面：项目真实性 + 执行链路细节

一上来就让你**完整讲 Agent 的执行链路**：用户输入需求以后，系统怎么识别意图、怎么拆任务、多个步骤谁先谁后、什么时候调模型、什么时候调工具、**不同任务又怎么选择模型**。

然后开始挖项目细节：

- 技术架构是怎么设计的；
- **长短期记忆怎么区分**，什么信息进长期记忆，记忆多了/长了这个"长度"怎么解决；
- **Context 窗口是多少、实际会用到多少、什么时候触发压缩、阈值怎么定、压缩以后重要信息丢了怎么办**；
- 后面甚至直接开始聊**成本**：不同任务怎么选模型、让 Agent 写一千行代码大概消耗多少 token、百万 token 怎么计费、一次任务成本多少。

所以我最大的感受是：**面试官不是在听你懂多少概念，而是在判断你的项目是不是真的跑过**。

- 你说做了上下文压缩 → 他就问为什么压、什么时候压、效果怎么评估；
- 你说用了 Memory → 他就问怎么存、怎么召回、数据膨胀怎么办；
- 你说用了 Tool Calling → 他就问调用失败怎么办、线上是怎么做的。

"如果你的项目只是跟着教程跑了一个 Demo，没有真正跑（过），链路里没有 memory、context、成本和异常处理，一面很容易就被问穿了。" 所以**一面本质上考项目真实性和技术细节**。

### 技术二面：给你一个项目，从零到一把它设计出来

方向明显变了：一面问"那是你做的吗"，二面问"**真给你一个项目，你能不能把它设计出来**"。

- 设计一个**企业级 Agent 系统**：整个系统怎么拆、用户请求进来怎么识别任务、怎么判断简单还是复杂任务、复杂任务怎么拆成 subtask、又怎么生成执行计划；
- 执行以后**怎么判断当前 step 成功还是失败**、工具超时了怎么办、什么时候重试、什么时候重新规划、任务执行失败怎么恢复；
- 问到 **Coding Agent**（应该就是 MiniMax Code）：要让 Agent 理解一个大型仓库代码，不可能把几十万行代码全部塞进 context，那怎么结合**向量检索、关键词搜索、AST 分析和调用链分析**构建当前任务需要的 coding context；
- **工具系统怎么设计**：工具怎么注册、schema 怎么定义、哪些工具只能读、哪些可以写、高风险操作怎么做权限控制；
- 还有 **DSH、OpenCode 这些开源 Harness** 应用的对比和使用。

所以二面真正考的是：**这个 Agent 如果明天交给企业使用，你能不能保证它稳定地跑**——多人使用会不会出问题、任务失败能不能恢复、工具有没有权限边界、token 成本能不能控制、模型输出异常怎么兜底、**版本更新以后怎么证明效果提升了**。

"大部分人学 Agent 只想到怎么让它跑起来，但生产环境或者说大厂真正需要解决的是**怎么让它长期稳定地跑**。" 所以二面考架构和工程化能力，而不是某个框架你会不会用。这也是很多公司喜欢招大厂的人的原因：换成 Agent 以后，模型是新的，但**高并发、容错、权限、监控、成本**这些老问题一样存在。

### CTO 面：动机、视野、个人价值

技术问题很少，主要问：

- 为什么选择 Agent 这个方向、对未来怎么看、**是因为最近几年火才做的还是准备长期做**；
- 有没有定期关注 AI 大事、**用过哪些最新的前沿模型**（ASR 听到像"OPUS 5.5 / GPT 6.1"，按当下口径应是 Opus 4.5 / GPT-5.1 一类）、对**全天候 Agent** 有什么看法；
- 觉得怎么学习才不会被 AI 时代淘汰；
- **你和其他候选人的差异是什么**（他的答法：不只是会调模型，也有工程落地和真实项目经验，而且在 2025 年 Agent 还没这么火的时候就已经系统学 Agent 相关的项目了）；
- 追问**你能给公司创造什么价值**（他的答法：拿一个真实落地项目讲——解决了什么问题、这些经验进 MiniMax 之后怎么迁移到他们的业务、如果让他负责这个方向准备怎么推进）；
- 最后甚至问：**如果入职以后给你配一个运营，让你单独负责一个 Agent，你有没有信心把它做到行业头部**。

CTO 面的感觉：**想拿高薪就得证明自己有独当一面的能力**。大厂需要的是能主动发现问题、推动项目、甚至独立负责一个方向并拿到结果的人，不是等别人分任务的。

### 收尾判断

- 技术一面看**项目真实性**（链路、任务拆解、Skill/memory/context、模型选型、token 成本）；
- 技术二面看**工程架构和个人能力**（稳定性、任务恢复、工具权限、成本控制、评测、能不能真正上线）；
- CTO 面看**个人价值和你对 AI 的理解程度**（为什么做、你和别人的差异、能给公司创造什么）。

"现在 Agent 开发已经到一个新阶段，**只会 prompt 调 API，或者跟教程做简单 Demo，肯定应付不了大厂面试**。" 他整理了近百份真实大模型面试录音（包括一些大厂和 AI 创业公司），一个明显变化是：**单纯问 Transformer、NLP 的越来越少，越来越问底层真实业务场景**。所以你的落地指标、实际业务场景一定要讲得非常深。准备转 Agent 的，一定要把项目里的**设计思路、技术选型、性能优化、异常处理、成本控制、效果评估**讲清楚。

"因为面试官其实更想知道的不是你会不会做 Agent，而是**这个 Agent 交给你之后，你能不能把它做上线**。"

## 4. 转写踩过的坑（给下次留）

1. `pip install --user` 在本机报 WinError 5 → 必须 `--target D:\TCL\leaning_AI_agent\.tmp-tools` + `$env:PYTHONPATH`。
2. hf-mirror 的 `model.bin` 会中途断流，`huggingface_hub` 只重试 3 次就放弃 → 用 `HEAD` 拿 `Content-Length` 后自己按 `Range` 续传到**字节数完全相等**（这次少了 15 MB，ctranslate2 直接 access violation，报错是 `exit=-1073741819`，看不出原因）。
3. `ctranslate2 4.8.5` 在本机加载模型即崩，降到 **4.5.0** 才正常。
4. `faster-whisper` 的 `vad_filter=True` 也会崩（onnxruntime 路径）→ 用 `vad_filter=False`。
5. PowerShell 控制台是 GBK，中文输出会乱码，但**文件本身没坏** → 直接 `open(..., encoding="utf-8")` 写文件再读，别信控制台。
