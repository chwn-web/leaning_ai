# ADR 0001：主线语言选 Python，TypeScript 只做前端层

- 状态：已采纳（2026-11-09）
- 决策者：你（学习者）
- 相关：[plan/00-总计划.md](../../../../plan/00-总计划.md) 第 0 节、[plan/04-资源清单.md](../../../../plan/04-资源清单.md) 第 4 节

## 背景

我是前端为主的全栈工程师，JS 熟练、Node 会用但不熟、Python 只是"读过能看懂"。要转 Agent 工程师（目标 2027 年入职）。

第一版计划我（助手）按"现有技能 + 最小阻力"把主语言定成 TypeScript，理由是"不用同时学两件事"。**你当场指出了这个判断的问题**：进公司写项目、面试考察，主流都是 Python，学习计划应该按目标岗位的主流语言排，而不是按我现在熟什么排。

## 决策

- **Python 是主线**：P0–P4 的服务端、Agent 编排、RAG、评测、MCP Server 全部 Python。
- **TypeScript 只做前端层**：平台 UI、流式交互、Copilot 组件、SDK 封装。
- 补语言不设独立阶段，在 W1–W2 与 P0 并行完成。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| **A. 全 TS**（第一版） | 与目标岗位脱节：LangGraph / LlamaIndex / DSPy / RAGAS / vLLM / 论文官方实现 / 主流开源 Agent 框架主体都是 Python。用 TS 会在读一手资料、面试答"你怎么实现的"、进团队后接手代码三处持续吃亏。 |
| **B. 全 Python** | 过度矫正。你的前端能力是稀缺项（能把 Agent 做成用户敢用的产品），丢掉它等于放弃差异化；P3 平台没有 UI 就讲不出"产品化"。 |
| **C. 先 TS 后转 Python** | 迁移成本最高：真写了 3 个项目再换语言，等于把 3 个项目的经验重写一遍，且前 6 个月的产出无法直接用于面试。 |

## 代价（诚实记录）

- 前两周会比"全 TS"慢：要同时处理"学语言"和"学 Agent 概念"。
- 缓解：骨架零第三方依赖 + 类型注解 + dataclass，Python 侧只用到很窄的语法子集（`W1` 补齐清单只有 6 条）。
- 风险：如果 W2 结束时还写不出 200 行能跑的 Python，就把 P0 缩到"只用两个模型 + 一个降级"，把语言练习挪到 W3–W4 项目里继续。

## 怎么验证这个决定对不对

1. **W2 检查点**：能不看资料写出"读 JSONL → 调工具 → 落 trace"的 150 行 Python，且 `python src/main.py` 跑通；
2. **W8 检查点**：能读懂所选框架（LangGraph / LlamaIndex）源码里的一次 `tool call` 流程；
3. **W12 检查点**：JD 词频统计里 "Python" 相关要求不再是我的缺口项；
4. **反悔条件**：若 3 月投递时发现目标公司清一色要 TS（概率低），再调整——但那时 TS 侧你也已经很强，属于低成本切换。
